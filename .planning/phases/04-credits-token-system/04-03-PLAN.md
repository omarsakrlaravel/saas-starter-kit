<objective>
Integrate the credit system with Stripe via Cashier for two flows: subscription renewal grants and one-time top-up purchases.

Purpose: Credits flow into organizations from two sources — subscription renewals (automatic) and top-up purchases (user-initiated). Both go through Stripe and fire webhooks that the existing HandleStripeWebhook listener processes. This plan extends that listener and adds a top-up checkout component.

Output: Subscription renewals grant credits_per_cycle automatically. Users can purchase credit packs via Stripe checkout.
</objective>

<task type="auto">
  <name>Task 1: Subscription renewal credit grants via webhook</name>
  <files>app/Listeners/HandleStripeWebhook.php, wave/src/Plan.php</files>
  <action>
  **Plan model** (`wave/src/Plan.php`):
  Add helper method:
  - `hasCredits(): bool` — returns `$this->credits_per_cycle !== null && $this->credits_per_cycle > 0`
  - Add `credits_per_cycle` to the casts method as `'integer'` if the casts method exists (check existing pattern)

  **HandleStripeWebhook** (`app/Listeners/HandleStripeWebhook.php`):
  Extend the `invoice.paid` handler to grant credits on subscription renewal.

  When an `invoice.paid` event fires for a subscription invoice (not a one-time payment):
  1. Find the subscription by `stripe_subscription_id` from the invoice
  2. If subscription has a `plan_id`, load the Plan
  3. If plan has `credits_per_cycle > 0`:
     - Resolve the billable (Organization or User — check billable_type)
     - If billable is an Organization:
       ```php
       $org->grantCredits(
           amount: $plan->credits_per_cycle,
           description: "Monthly credit grant ({$plan->name})",
           idempotencyKey: "sub_renewal_{$invoice->id}",
       );
       ```
     - The idempotencyKey uses the Stripe invoice ID to prevent duplicate grants from webhook retries
  4. If billable is a User (personal subscription), skip credit granting — credits are org-level

  **Important:** Only grant on renewal invoices, not the initial subscription invoice. Detect this by checking if the subscription was just created (compare invoice dates with subscription creation) or by checking if this is the first invoice for the subscription. Alternatively, grant on ALL subscription invoices including the first one — the product builder can adjust. Document the choice.

  Place the credit granting logic in a dedicated private method: `handleSubscriptionCreditGrant(Subscription $subscription, $stripeInvoice): void`

  Use CreditService directly (resolve from container) rather than HasCredits trait, since the webhook handler operates at the system level.
  </action>
  <verify>Write a test in `tests/Feature/CreditStripeIntegrationTest.php` that creates an org with a subscription on a plan with credits_per_cycle=1000, simulates an `invoice.paid` webhook payload, and asserts the org received 1000 credits with correct idempotency key. Also test that firing the same webhook twice only grants once (idempotency).</verify>
  <done>Subscription renewal webhook grants credits_per_cycle to the organization. Idempotency prevents duplicate grants from webhook retries. Credits not granted for user-level subscriptions.</done>
</task>

<task type="auto">
  <name>Task 2: Credit top-up checkout via Stripe</name>
  <files>wave/src/Http/Livewire/Billing/TopUpCheckout.php, wave/routes/web.php, app/Listeners/HandleStripeWebhook.php</files>
  <action>
  **TopUpCheckout Livewire component** (`wave/src/Http/Livewire/Billing/TopUpCheckout.php`):
  Create a Livewire component that lists available credit packs and initiates Stripe checkout.

  Properties:
  - `public array $packs` — loaded from `config('credits.packs')`
  - `public ?string $selectedPackId` — selected pack's price_id

  Methods:
  - `mount()`: Load packs from config, filter to only packs with valid price_id
  - `purchasePack(string $priceId)`:
    1. Find the pack config by price_id
    2. Get the billing context (organization) — follow the pattern from existing Checkout component
    3. Create Stripe checkout session using Cashier's `checkout()`:
       ```php
       $user = auth()->user();
       return $user->checkout([$priceId => 1], [
           'success_url' => route('settings.credits') . '?topup=success',
           'cancel_url' => route('settings.credits') . '?topup=cancelled',
           'mode' => 'payment',
           'metadata' => [
               'type' => 'credit_topup',
               'credits' => $pack['credits'],
               'organization_id' => $org->id,
               'user_id' => $user->id,
           ],
       ]);
       ```
    4. Return the redirect to Stripe checkout

  Register the component in WaveServiceProvider or let Livewire auto-discover it.

  **Route** (`wave/routes/web.php`):
  No new route needed — the component will be embedded in the credits settings page (Plan 05). But register the component name if not auto-discovered.

  **Webhook handler extension** (`app/Listeners/HandleStripeWebhook.php`):
  Extend the `checkout.session.completed` handler:

  When processing a completed checkout session:
  1. Check metadata for `'type' => 'credit_topup'`
  2. If found:
     - Extract `credits`, `organization_id`, `user_id` from metadata
     - Load the Organization
     - Grant credits:
       ```php
       $creditService->grantCredits(
           org: $org,
           amount: (int) $metadata['credits'],
           description: "Credit top-up ({$metadata['credits']} credits)",
           user: User::find($metadata['user_id']),
           idempotencyKey: "topup_{$checkoutSession->id}",
       );
       ```
  3. The idempotencyKey uses the checkout session ID to prevent duplicate grants

  Add a dedicated private method: `handleCreditTopUp(array $metadata, $checkoutSession): void`
  </action>
  <verify>Add tests to `CreditStripeIntegrationTest.php`: simulate a `checkout.session.completed` webhook with credit_topup metadata, assert credits were granted to the correct org. Test idempotency (same session ID twice). Test that non-topup checkouts are not affected.</verify>
  <done>TopUpCheckout component renders available packs and redirects to Stripe. Webhook processes completed top-up checkout and grants credits. Idempotency prevents duplicate grants.</done>
