<feature>
  <name>Credit ledger with correctness invariants</name>
  <files>wave/src/Services/CreditService.php, wave/src/Traits/HasCredits.php, app/Models/Organization.php, tests/Feature/CreditLedgerTest.php</files>
  <behavior>
  **Invariant 1 — Race condition protection:**
  - Org has 600 balance
  - Two concurrent consumeCredits(500) calls
  - Expected: exactly one succeeds (returns CreditTransaction), one fails (returns false)
  - After: balance_cached is 100, exactly one CreditTransaction recorded
  - Implementation: Use `SELECT ... FOR UPDATE` (pessimistic lock on organization row) within DB::transaction

  **Invariant 2 — Idempotency:**
  - consumeCredits(100, idempotencyKey: 'req-123') called twice on same org
  - Expected: one CreditTransaction entry, balance decremented once
  - Second call returns the existing CreditTransaction (not false, not a new entry)
  - Implementation: Check idempotency_key existence before insert, return existing if found

  **Invariant 3 — Balance consistency:**
  - After any sequence of grants and consumptions
  - balance_cached on organization always equals SUM(credit_transactions.amount) for that org
  - Implementation: Update balance_cached atomically within the same DB transaction as the ledger entry

  **Invariant 4 — Transaction atomicity:**
  - grantCredits(1000) inside a DB::transaction that throws after the grant
  - Expected: grant rolled back, balance_cached unchanged, no CreditTransaction
  - Implementation: CreditService uses DB::transaction internally (becomes savepoint when nested)

  **Additional behaviors:**
  - grantCredits($org, 500, 'subscription_renewal') → creates Grant entry, updates balance_cached, dispatches CreditsGranted event
  - consumeCredits($org, 100, 'api_call') → creates Consume entry (negative amount), updates balance_cached, dispatches CreditsConsumed, checks low_threshold → CreditsLow, checks zero → CreditsDepleted
  - consumeCredits on insufficient balance → returns false, no entry created
  - refundCredits($org, 50, 'refund for failed request', referenceTx) → creates Refund entry referencing original
  - adjustBalance($org, +200, 'admin adjustment', $adminUser) → creates Adjustment entry

  **HasCredits trait interface:**
  - `$org->consumeCredits(int $amount, string $description, ?string $idempotencyKey = null): CreditTransaction|false`
  - `$org->grantCredits(int $amount, string $description, ?string $idempotencyKey = null): CreditTransaction`
  - `$org->refundCredits(int $amount, string $description, ?CreditTransaction $reference = null): CreditTransaction`
  - `$org->creditBalance(): int` — returns balance_cached
  - `$org->hasSufficientCredits(int $amount): bool`
  - `$org->creditTransactions(): HasMany` — relationship to CreditTransaction
  All trait methods delegate to CreditService resolved from the container.
  </behavior>
  <implementation>
  **CreditService** (`wave/src/Services/CreditService.php`):

  `grantCredits(Organization $org, int $amount, string $description, ?User $user = null, ?string $idempotencyKey = null, ?Model $reference = null, ?array $metadata = null): CreditTransaction`
  - Validate amount > 0
  - If idempotencyKey provided, check for existing — return it if found
  - DB::transaction with lockForUpdate on organization
  - Calculate new balance: org.balance_cached + amount
  - Create CreditTransaction with type=Grant, amount=+amount, balance_after=newBalance
  - Update org.balance_cached = newBalance
  - Dispatch CreditsGranted event
  - Return the transaction

  `consumeCredits(Organization $org, int $amount, string $description, ?User $user = null, ?string $idempotencyKey = null, ?Model $reference = null, ?array $metadata = null): CreditTransaction|false`
  - Validate amount > 0
  - If idempotencyKey provided, check for existing — return it if found
  - DB::transaction with lockForUpdate on organization
  - Reload balance: $org->lockForUpdate()->first()->balance_cached
  - If balance < amount → return false (inside transaction, nothing committed)
  - Calculate new balance: balance - amount
  - Create CreditTransaction with type=Consume, amount=-amount, balance_after=newBalance
  - Update org.balance_cached = newBalance
  - Dispatch CreditsConsumed event
  - If newBalance <= config('credits.low_threshold') → dispatch CreditsLow
  - If newBalance === 0 → dispatch CreditsDepleted
  - Return the transaction

  `refundCredits(Organization $org, int $amount, string $description, ?User $user = null, ?CreditTransaction $reference = null): CreditTransaction`
  - Same pattern as grant but with type=Refund and optional reference

  `adjustBalance(Organization $org, int $amount, string $description, ?User $user = null): CreditTransaction`
  - Same pattern, type=Adjustment, amount can be positive or negative

  `balance(Organization $org): int`
  - Return org.balance_cached

  `verifyBalance(Organization $org): bool`
  - Compare balance_cached with SUM(credit_transactions.amount) for that org
  - Return true if matching, false if diverged

  **HasCredits trait** (`wave/src/Traits/HasCredits.php`):
  Each method resolves CreditService from container and delegates. Pattern:
  ```php
  public function consumeCredits(int $amount, string $description, ?string $idempotencyKey = null): CreditTransaction|false
  {
      return app(CreditService::class)->consumeCredits($this, $amount, $description, idempotencyKey: $idempotencyKey);
  }
  ```

  Add `use HasCredits` to Organization model.
  </implementation>
