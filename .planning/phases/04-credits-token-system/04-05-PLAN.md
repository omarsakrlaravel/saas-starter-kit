<task type="auto">
  <name>Task 1: Credit balance header component</name>
  <files>resources/themes/anchor/components/app/credit-balance.blade.php</files>
  <action>
  Create an anonymous Blade component that displays the current credit balance with color coding.

  **Component:** `resources/themes/anchor/components/app/credit-balance.blade.php`

  Check if the credits system is enabled (`config('credits.enabled')`) — if not, render nothing.

  Check if the current user's organization has the HasCredits trait / has a plan with credits_per_cycle. If the org has no credit activity and plan has no credits, don't show the component. Use a simple check: `$org->balance_cached > 0 || $org->creditTransactions()->exists()` or check if the plan has credits_per_cycle.

  **Display:**
  - A small pill/badge showing the credit count number
  - Clickable — links to `route('settings.credits')`
  - Color shift based on balance relative to plan allowance:
    - Green: > 50% of credits_per_cycle remaining
    - Yellow: 10-50% remaining
    - Red: < 10% remaining or below config('credits.low_threshold')
    - If no credits_per_cycle on plan, use absolute thresholds from config

  **Implementation:**
  Use Alpine.js for reactive class binding:
  ```blade
  @php
      $org = auth()->user()->currentOrganization;
      $balance = $org?->balance_cached ?? 0;
      $plan = auth()->user()->activeBillingSubscription()?->plan;
      $total = $plan?->credits_per_cycle ?? 0;
  @endphp

  @if(config('credits.enabled') && ($balance > 0 || $total > 0))
  <a href="{{ route('settings.credits') }}" class="..." title="Credits remaining">
      {{-- Color-coded balance display --}}
  </a>
  @endif
  ```

  Follow existing component patterns in the theme — check sibling files for Tailwind classes and dark mode support.

  **Integration:** Find where the app header/navigation includes user-facing elements (likely `resources/themes/anchor/components/app/header.blade.php` or similar) and include this component. Place it near the notifications bell or user menu. Search for where notifications or user menu items are rendered to find the right location.
  </action>
  <verify>Start dev server. Log in as a user with an org that has credits. Verify the credit balance appears in the header. Verify clicking it navigates to the credits page. Check dark mode compatibility.</verify>
  <done>Credit balance pill visible in app header with color-coded urgency. Clickable, links to credits page. Hidden when credits system disabled or org has no credit activity.</done>
</task>

<task type="auto">
  <name>Task 2: Credits settings page with history and top-up</name>
  <files>resources/themes/anchor/pages/settings/credits.blade.php, resources/themes/anchor/components/app/settings-layout.blade.php</files>
  <action>
  **Credits settings page** (`resources/themes/anchor/pages/settings/credits.blade.php`):
  Create as a Folio page following the existing settings page pattern (see invoices.blade.php for reference).

  Page setup:
  ```php
  <?php
  use function Laravel\Folio\{name, middleware};
  name('settings.credits');
  middleware(['auth', 'verified']);
  ?>
  ```

  **Page content (use Volt inline component for reactivity):**

  1. **Balance summary section:**
     - Current balance: large number display
     - Plan allowance: "X of Y credits remaining this cycle" (if plan has credits_per_cycle)
     - Next renewal date from active subscription (if exists)
     - Visual progress bar showing usage (balance / credits_per_cycle)

  2. **Buy more credits section:**
     - List credit packs from `config('credits.packs')` as cards
     - Each card shows: pack name, credit amount, price (from Stripe — or just the name since price is in Stripe)
     - "Buy" button on each pack triggers the TopUpCheckout component's purchasePack method
     - If no packs configured, show a message: "Credit packs are not yet configured"
     - Handle `?topup=success` query param to show success notification

  3. **Transaction history section:**
     - Paginated table showing recent credit transactions
     - Columns: Date, Type (badge), Amount (+/-), Balance After, Description
     - Use Alpine.js pagination (follow invoices.blade.php pattern) or Livewire pagination
     - Query: `$org->creditTransactions()->latest()->paginate(15)`
     - Type badges: Grant = green, Consume = orange, Refund = blue, Adjustment = gray

  Wrap everything in `<x-app.settings-layout>` following the existing pattern.

  **Settings layout navigation** (`resources/themes/anchor/components/app/settings-layout.blade.php`):
  Add a "Credits" nav link in the sidebar, near "Invoices":
  ```blade
  <x-settings-sidebar-link :href="route('settings.credits')" icon="phosphor-coins-duotone">Credits</x-settings-sidebar-link>
  ```

  Only show this link when `config('credits.enabled')` is true. Check existing sidebar links for the conditional pattern (or wrap in `@if`).
  </action>

Verify the "Buy more" section lists configured packs (or empty state if none configured). Check the settings sidebar shows the Credits link. Run `vendor/bin/pint --dirty --format agent`.</verify>
