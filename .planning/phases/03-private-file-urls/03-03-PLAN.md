<task type="auto">
  <name>Task 1: Rewire avatar upload in profile settings page</name>
  <files>resources/themes/anchor/pages/settings/profile.blade.php</files>
  <action>
  Modify the `saveNewUserAvatar()` method in the Volt component to use FileService instead of direct Storage::disk('public') calls.

  **Current flow:**
  1. Base64 image from Croppie.js → `$this->avatar`
  2. intervention/image reads and resizes to 800x800
  3. `Storage::disk('public')->put('avatars/{username}.png', $encoded)`
  4. Sets `auth()->user()->avatar = $path`

  **New flow:**
  1. Base64 image from Croppie.js → `$this->avatar` (unchanged)
  2. intervention/image reads and resizes to 800x800 (unchanged)
  3. Get the encoded image content: `$encoded = $image->encode()->toString()` (or however intervention/image v3 encodes — check the current code pattern)
  4. Call FileService::storeFromContent():
     ```php
     $fileService = app(\Wave\Services\FileService::class);
     $file = $fileService->storeFromContent(
         content: $encoded,
         filename: auth()->user()->username . '.png',
         mimeType: 'image/png',
         user: auth()->user(),
         organization: null,  // avatars are personal, not org-scoped
         directory: 'avatars',
         accessLevel: \App\Enums\FileAccessLevel::AppPublic,
         fileable: auth()->user(),  // attach to User via morphTo
     );
     ```
  5. Update user avatar column to store the File UUID: `auth()->user()->avatar = $file->uuid;`
  6. Save user and log activity (unchanged)
  7. Delete old avatar file if it was a previous private file (look up old File by previous UUID if it was a UUID, delete via FileService::delete())

  **Important:** The old avatar value might be a legacy path (like `demo/default.png` or `avatars/username.png` on public disk) or a File UUID (from a previous private upload). Handle both cases:
  - If old avatar is a UUID and a File record exists → delete old file via FileService
  - If old avatar is a legacy path → just overwrite the user column (don't try to delete from public disk — leave legacy files for manual cleanup)

  The Croppie.js frontend and modal remain unchanged — only the server-side storage method changes.
  </action>

  <done>Avatar upload creates File record with access_level=app_public, stores image on private disk, updates user.avatar with File UUID.</done>

  <files>wave/src/User.php, app/Filament/Resources/Users/UserResource.php, app/Filament/Resources/Members/MemberResource.php</files>
  <action>
  **User model** (`wave/src/User.php`):

  Add a relationship and modify the `avatar()` method:

  1. Add `avatarFile()` relationship:
     ```php
     public function avatarFile(): \Illuminate\Database\Eloquent\Relations\MorphOne
     {
         return $this->morphOne(\Wave\File::class, 'fileable');
     }
     ```

  2. Modify `avatar()` method to handle both legacy paths and File UUIDs:
     ```php
     public function avatar(): string
     {
         // No avatar set — return default
         if (empty($this->attributes['avatar']) || $this->attributes['avatar'] === 'demo/default.png') {
             return Storage::disk('public')->url('demo/default.png');
         }

         // Check if avatar is a UUID (from private file system)
         if (Str::isUuid($this->attributes['avatar'])) {
             $file = $this->avatarFile;
             if ($file) {
                 return app(\Wave\Services\FileService::class)->signedUrl($file);
             }
             // Fallback if File record missing
             return Storage::disk('public')->url('demo/default.png');
         }

         // Legacy path on public disk
         return Storage::disk('public')->url($this->attributes['avatar']);
     }
     ```

  3. Add `Str` import if not already present.

  **Important performance consideration:** The `avatarFile` morphOne relationship should be eager-loaded in queries that display multiple users. Add `avatarFile` to a `$with` property or document the eager-loading recommendation. Do NOT add it to `$with` globally (it would affect every User query). Instead, add a scope:
     ```php
     public function scopeWithAvatarFile(Builder $query): Builder
     {
         return $query->with('avatarFile');
     }
     ```
