  <name>Task 2: Add status columns, badge, filters, and suspend/unsuspend actions to UserResource</name>
  <files>app/Filament/Resources/Users/UserResource.php</files>
  <action>
  Modify `UserResource` to expose account status in the table and provide admin actions.

  **Table columns -- add after the existing `username` column:**
  - `TextColumn::make('status')` with `->badge()` and color mapping:
    - `active` = success (green)
    - `restricted` = warning (yellow/amber)
    - `suspended` = danger (red)
  - Use `->formatStateUsing(fn ($state) => $state->label())` to render the enum label
  - `TextColumn::make('status_reason')` toggleable, hidden by default

  **Table filters -- add alongside existing filters:**
  - `SelectFilter::make('status')` with options from `AccountStatus` enum cases mapped to their labels

  **Table record actions -- add before the existing Impersonate action:**
  - **Suspend action:**
    - `Action::make('suspend')` with danger color and a shield/ban icon
    - Visible only when the record is NOT already suspended: `->visible(fn (User $record): bool => !$record->isSuspended())`
    - Opens a modal with `requiresConfirmation()` and a form containing:
      - `Textarea::make('reason')->required()->maxLength(1000)->label('Suspension Reason')` -- admin must provide a reason
      - `Select::make('status')->options(['restricted' => 'Restrict (billing/warning)', 'suspended' => 'Suspend (full block)'])->required()->default('suspended')`
    - Action handler:
      - Resolve target `AccountStatus` from form data
      - Call `$record->recordStatusTransition(...)` with reason, `auth()->id()` as applied_by, and null expires_at
      - Send success `Notification` with the user's name and new status
    - `modalDescription('This will change the user account status. Restricted users can access billing and support. Suspended users are fully blocked.')`

  - **Unsuspend action:**
    - `Action::make('unsuspend')` with success color and a check/unlock icon
    - Visible only when the record IS restricted or suspended: `->visible(fn (User $record): bool => $record->isRestricted() || $record->isSuspended())`
    - Opens a modal with `requiresConfirmation()`
    - Action handler:
      - Call `$record->recordStatusTransition(AccountStatus::Active, 'Unsuspended by admin', auth()->id())`
      - Send success `Notification`
    - `modalDescription('This will restore the user to active status.')`

  **Form -- add to the right-side "Status & Access" section:**
  - Display-only `Placeholder` or read-only `TextInput` showing current `status` value
  - Display-only `TextInput` showing `status_reason` (read-only, visible when not null)
  - These are read-only because status changes should go through the table actions (which record history), not through direct form edits
  </action>
  <verify>
  - `php -d detect_unicode=0 -l app/Filament/Resources/Users/UserResource.php`
  - Visually confirm: status column, filter, and both actions are present in the table definition
  </verify>
