<task type="auto">
  <name>Task 1: Write comprehensive tenant isolation feature tests</name>
  <files>tests/Feature/TenantScopingTest.php</files>
  <action>
  Create `tests/Feature/TenantScopingTest.php` using Pest style (project convention).

  Use `php artisan make:test --pest TenantScopingTest` to scaffold, then replace contents.

  Test setup (beforeEach):
  - Create 2 organizations via factory
  - Create 2 users, each as owner of one org
  - Set `current_organization_id` on each user to their org
  - Create test data: ActivityLog entries for each org (2 per org, 4 total)

  Test cases to write:

  **Read scoping tests:**
  1. `it('scopes queries to current tenant when context is set')`:
     - Set TenantContext to org A
     - Query `ActivityLog::all()`
     - Expect only org A records (count 2)
     - Verify none have org B's id

  2. `it('returns all records when no tenant context is set')`:
     - Do NOT set TenantContext
     - Query `ActivityLog::all()`
     - Expect all 4 records

  3. `it('prevents cross-tenant data access')`:
     - Set TenantContext to org A
     - Try to find an ActivityLog that belongs to org B by its ID
     - Expect null (not found -- scope blocks it)

  4. `it('scopes relationship queries')`:
     - Set TenantContext to org A
     - Query via relationship or where clause
     - Verify scope applies to relationship queries too

  **Write scoping tests:**
  5. `it('auto-fills organization_id on create when context is set')`:
     - Set TenantContext to org A
     - Create new ActivityLog without specifying organization_id
     - Verify organization_id equals org A's id

  6. `it('does not override explicitly set organization_id')`:
     - Set TenantContext to org A
     - Create new ActivityLog WITH organization_id set to org B
     - Verify organization_id remains org B (explicit wins)

  7. `it('leaves organization_id null when no context is set')`:
     - Do NOT set TenantContext
     - Create new ActivityLog without organization_id
     - Verify organization_id is null

  **Scope bypass tests:**
  8. `it('allows bypassing scope with withoutGlobalScope')`:
     - Set TenantContext to org A
     - Query `ActivityLog::withoutGlobalScope(TenantScope::class)->get()`
     - Expect all 4 records

  **Middleware integration tests:**
  9. `it('sets tenant context for authenticated user with organization')`:
     - Acting as user with current_organization_id set
     - Make a web request
     - Verify TenantContext has the correct org id after request

  10. `it('does not set tenant context for user without organization')`:
      - Acting as user with null current_organization_id
      - Make a web request
      - Verify TenantContext has() returns false

  11. `it('does not set tenant context for unauthenticated requests')`:
      - Make unauthenticated web request
      - Verify TenantContext has() returns false

  **ActivityLog::log() integration:**
  12. `it('captures organization_id in activity log entries')`:
      - Set TenantContext to org A
      - Acting as user in org A
      - Call ActivityLog::log('test_action', 'test')
      - Verify the created log has organization_id set to org A

  Follow Pest conventions from existing tests:
  - Use `expect()` with chaining
  - Use `beforeEach()` for setup
  - Use `actingAs()` for authenticated requests
  - Use factories where available (User::factory(), Organization model creation)
  - Since Organization doesn't have a factory, create it directly with required fields
  </action>
  <verify>
  `php artisan test --compact tests/Feature/TenantScopingTest.php` -- all tests pass
  </verify>
  <done>12+ test cases covering read scoping, write scoping, scope bypass, middleware integration, and ActivityLog::log() integration. All pass.</done>
</task>

<task type="auto">
  <name>Task 2: Audit existing queries for scope gaps</name>
  <files>None specifically -- this is an audit task that may result in fixes to various files</files>
  <action>
  Audit the codebase for potential tenant scope gaps. Search for patterns that could bypass tenant scoping:

  1. **Direct DB facade usage on tenant tables:**
     - Search for `DB::table('activity_logs')` and `DB::table('api_keys')` -- these bypass Eloquent scopes
     - If found: either convert to Eloquent or add manual where clause

  2. **withoutGlobalScopes() usage:**
     - Search for `withoutGlobalScopes()` and `withoutGlobalScope(` across the codebase
     - Document any existing usages (these are pre-Phase-1 and won't reference TenantScope, but note them for awareness)

  3. **Raw queries:**
     - Search for `DB::select`, `DB::statement`, `DB::raw` that reference tenant tables
     - If found: flag as potential scope gap

  4. **ActivityLog::log() in queue context:**
     - The `CreateActivityLog` job dispatches activity log creation
     - Verify that the job receives organization_id in the data payload (already handled in Plan 01 by capturing org at dispatch time)
     - Read `wave/src/Jobs/CreateActivityLog.php` to confirm it passes data through correctly

  5. **ApiKey creation paths:**
     - Search for where ApiKeys are created in the codebase
     - Verify those paths will have TenantContext set (web routes) or explicitly set organization_id

  6. **Model factory updates:**
     - Check if ActivityLog and ApiKey have factories
     - If they do, the factory should NOT set organization_id by default (let the trait handle it in test context, or set it explicitly in tests)
     - If factories don't exist, no action needed

  For each gap found:
  - Fix it if straightforward (< 5 lines change)
  - Document it in the SUMMARY.md if it requires broader changes (deferred to future phases)

  Do NOT create a TenantScopeBypassDetector in this phase -- that's a future enhancement. The audit is the manual version of that guardrail.
  </action>
