<task type="auto">
  <name>Task 1: Create TenantContext resolver and TenantScope global scope</name>
  <files>wave/src/TenantContext.php, wave/src/Scopes/TenantScope.php</files>
  <action>
  Create `wave/src/TenantContext.php`:
  - Simple class with `set(?int $organizationId)`, `get(): ?int`, and `has(): bool` methods
  - Stores the current organization ID for the request lifecycle
  - Namespace: `Wave`
  - No constructor dependencies -- pure value holder

  Create directory `wave/src/Scopes/` and create `wave/src/Scopes/TenantScope.php`:
  - Implements `Illuminate\Database\Eloquent\Scope`
  - In `apply(Builder $builder, Model $model)`:
    - Resolve `TenantContext` from the container via `app(TenantContext::class)`
    - If `$context->has()` is true, add `->where($model->getTable() . '.organization_id', $context->get())`
    - If `$context->has()` is false, do NOTHING (no scope applied -- this is critical for admin, console, queue workers)
  - Namespace: `Wave\Scopes`

  Design principle: TenantContext drives everything. No context = no scope. This naturally handles admin panel, artisan commands, and queue workers without any special-casing.
  </action>
  <verify>
  - Files exist at the correct paths
  - `php artisan tinker --execute="new Wave\TenantContext()"` runs without error
  - `php artisan tinker --execute="new Wave\Scopes\TenantScope()"` runs without error
  </verify>
  <done>TenantContext and TenantScope classes exist, are autoloadable, and follow the design: no context = no scope applied</done>
</task>

<task type="auto">
  <name>Task 2: Create BelongsToTenant trait, migration, and apply to models</name>
  <files>wave/src/Traits/BelongsToTenant.php, database/migrations/2026_02_26_000001_add_organization_id_to_tenant_tables.php, wave/src/ActivityLog.php, wave/src/ApiKey.php</files>
  <action>
  Create `wave/src/Traits/BelongsToTenant.php`:
  - Namespace: `Wave\Traits`
  - In `bootBelongsToTenant()` (static boot method):
    - `static::addGlobalScope(new TenantScope)` to auto-scope all queries
    - `static::creating(function (Model $model) {...})` to auto-fill `organization_id`:
      - Resolve TenantContext from container
      - If `$context->has()` AND `$model->organization_id` is null, set `$model->organization_id = $context->get()`
      - If context has no org, leave organization_id alone (caller must set it explicitly or DB constraint catches it)
  - Add `organization(): BelongsTo` relationship method returning `$this->belongsTo(Organization::class)`
  - Import `App\Models\Organization`, `Wave\Scopes\TenantScope`, `Wave\TenantContext`
  - Follow existing trait conventions from HasPlanFeatures and HasProfileKeyValues (PHPDoc, return types)

  Create migration `database/migrations/2026_02_26_000001_add_organization_id_to_tenant_tables.php`:
  - Use anonymous class style (project convention)
  - Add `organization_id` to `activity_logs` table:
    - `$table->foreignId('organization_id')->nullable()->after('user_id')->constrained('organizations')->nullOnDelete()`
    - `$table->index('organization_id')` for query performance
  - Add `organization_id` to `api_keys` table:
    - `$table->foreignId('organization_id')->nullable()->after('user_id')->constrained('organizations')->nullOnDelete()`
    - `$table->index('organization_id')`
  - Column is NULLABLE because existing records won't have an org, and personal-context records may not have one
  - Use `nullOnDelete` (not cascade) -- deleting an org shouldn't destroy activity logs, just orphan them
  - Down method drops the columns from both tables

  Apply BelongsToTenant trait:
  - Add `use BelongsToTenant;` to `wave/src/ActivityLog.php`
  - Add `use BelongsToTenant;` to `wave/src/ApiKey.php`
  - Add `'organization_id'` to ActivityLog's `$fillable` array
  - Add `'organization_id'` to ApiKey's `$fillable` array
  - Update the PHPDoc block on ActivityLog to include `@property int|null $organization_id`

  Also update ActivityLog::log() static method:
  - After setting `user_id` in the $data array, add `organization_id` from TenantContext:
    ```
    $context = app(TenantContext::class);
    if ($context->has()) {
        $data['organization_id'] = $context->get();
    }
    ```
  - This ensures queued activity logs also capture the org context at dispatch time (not execution time)
  </action>
  <verify>
  - `php artisan migrate` runs successfully
  - `php artisan tinker --execute="use Wave\ActivityLog; echo in_array('organization_id', (new ActivityLog)->getFillable()) ? 'yes' : 'no';"` outputs "yes"
  - `php artisan tinker --execute="echo method_exists(Wave\ActivityLog::class, 'organization') ? 'yes' : 'no';"` outputs "yes"
  - `php artisan tinker --execute="echo in_array(Wave\Scopes\TenantScope::class, array_keys(Wave\ActivityLog::resolveGlobalScopes())) ? 'yes' : 'no';"` outputs "yes" (global scope registered)
  </verify>
  <done>BelongsToTenant trait exists with auto-scoped reads + auto-filled writes. Migration adds nullable organization_id to activity_logs and api_keys. Both models use the trait. ActivityLog::log() captures org context at dispatch time.</done>
