<task type="auto">
  <name>Task 1: Register TenantContext singleton and create TenantAware middleware</name>
  <files>wave/src/WaveServiceProvider.php, wave/src/Http/Middleware/TenantAware.php</files>
  <action>
  Register TenantContext as a singleton in `WaveServiceProvider::register()`:
  - Add `$this->app->singleton(TenantContext::class);` in the `register()` method
  - Place it near the existing `$this->app->singleton('wave', ...)` registration
  - Import `Wave\TenantContext` at the top of the file
  - A plain `singleton(TenantContext::class)` with no factory closure is sufficient -- Laravel will auto-resolve the zero-argument constructor

  Create `wave/src/Http/Middleware/TenantAware.php`:
  - Namespace: `Wave\Http\Middleware`
  - Constructor injection: `public function __construct(private TenantContext $context) {}`
  - `handle(Request $request, Closure $next): Response` method:
    1. Check if user is authenticated: `if ($user = $request->user())`
    2. If authenticated AND user has `current_organization_id` set (not null):
       - Set context: `$this->context->set($user->current_organization_id)`
    3. If not authenticated or no current_organization_id, do nothing (context remains empty = no scoping)
    4. Return `$next($request)`
  - Keep it simple. Do NOT validate org membership here -- that's already handled by `User::getBillingContext()` and `setBillingContext()`. The middleware trusts that `current_organization_id` was set correctly via the existing org-switching flow.
  - Import: `Illuminate\Http\Request`, `Closure`, `Symfony\Component\HttpFoundation\Response`, `Wave\TenantContext`
  </action>
  <verify>
  - File exists at `wave/src/Http/Middleware/TenantAware.php`
  - `php artisan tinker --execute="app(Wave\TenantContext::class) === app(Wave\TenantContext::class) ? 'singleton' : 'not singleton'"` outputs "singleton"
  </verify>
  <done>TenantContext registered as singleton in WaveServiceProvider. TenantAware middleware resolves org from authenticated user's current_organization_id and sets TenantContext.</done>
</task>

<task type="auto">
  <name>Task 2: Register TenantAware middleware on web routes</name>
  <files>bootstrap/app.php</files>
  <action>
  Add TenantAware middleware to the web middleware stack in `bootstrap/app.php`:
  - Add `$middleware->web(\Wave\Http\Middleware\TenantAware::class);` in the `withMiddleware` callback
  - Place it AFTER the existing `HandleOrganizationInvite` middleware (org context should be resolved after invite handling)
  - Add the import at the top if needed (though the existing file uses FQCN strings in some places -- follow the existing pattern which uses FQCN with `::class`)

  Why web middleware only (not a global or named middleware):
  - Web routes are where authenticated users interact with tenant-scoped data
  - API routes use JWT auth which may resolve differently (future concern -- API can add its own tenant resolution)
  - Admin panel (Filament) uses its own middleware stack and should NOT have tenant scoping
  - Console commands have no request context -- TenantContext stays empty naturally
  - Queue workers have no request context -- TenantContext stays empty naturally (Phase 1 scope; TenantAware job trait is a future enhancement)

  Do NOT add the middleware to:
  - Filament panel middleware
  - API middleware
  - Global middleware stack
  </action>
  <verify>
  - `php artisan tinker --execute="echo 'ok';"` runs without error (app boots cleanly)
  - Check bootstrap/app.php has TenantAware in the web middleware chain
  - Start a quick route test: `php artisan test --compact` to verify no breakage
  </verify>
  <done>TenantAware middleware registered on web routes, after HandleOrganizationInvite. Admin, API, console, and queue are naturally unscoped.</done>
</task>
