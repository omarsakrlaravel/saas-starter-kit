<task type="auto">
  <name>Task 1: Test Pennant integration -- scope resolution, plan-gated, rollout, kill switch</name>
  <files>tests/Feature/FeatureFlagsTest.php</files>
  <action>
Create `tests/Feature/FeatureFlagsTest.php` using `php artisan make:test FeatureFlagsTest --pest --no-interaction`.

Use `Laravel\Pennant\Feature` facade. Use `Feature::flushCache()` in `beforeEach` to reset Pennant's in-memory cache between tests. Use `Feature::purge()` to clear stored values where needed.

**Test cases:**

1. **default scope resolves to organization via TenantContext**
   - Create a User with an Organization
   - Set TenantContext to the organization's ID
   - Act as the user
   - Define a test feature inline: `Feature::define('test-org-scope', fn ($scope) => $scope instanceof \App\Models\Organization)`
   - Assert `Feature::active('test-org-scope')` is true (scope resolved to Organization, not User)
   - Clean up: `Feature::purge('test-org-scope')`

2. **default scope falls back to user when no tenant context**
   - Create a User (no organization context)
   - TenantContext remains empty (do not set it)
   - Act as user
   - Define: `Feature::define('test-user-scope', fn ($scope) => $scope instanceof \App\Models\User)`
   - Assert `Feature::active('test-user-scope')` is true
   - Clean up

3. **plan-gated feature resolves based on plan features array**
   - Create Organization with a subscription on a Plan that has `features` JSON including 'ai-reports'
   - Set TenantContext to org
   - Assert `Feature::active('ai-reports')` is true (AiReports class resolves based on plan features)
   - Create another Organization with a Plan that does NOT include 'ai-reports' in features
   - Assert `Feature::for($otherOrg)->active('ai-reports')` is false

4. **plan-gated feature returns false for org without subscription**
   - Create Organization with no subscription
   - Set TenantContext to org
   - Assert `Feature::active('ai-reports')` is false

5. **kill switch defaults to inactive**
   - Assert `Feature::for(null)->active('maintenance-mode')` is false (default from MaintenanceMode::resolve)

6. **kill switch can be activated and deactivated globally**
   - `Feature::for(null)->activate('maintenance-mode')`
   - Assert `Feature::for(null)->active('maintenance-mode')` is true
   - `Feature::for(null)->deactivate('maintenance-mode')`
   - Assert `Feature::for(null)->active('maintenance-mode')` is false

7. **kill switch is scope-independent** (activating for null does not affect org scope)
   - Create Organization, set TenantContext
   - `Feature::for(null)->activate('maintenance-mode')`
   - Assert `Feature::for(null)->active('maintenance-mode')` is true
   - Assert checking with org scope does NOT automatically trigger kill switch (this verifies kill switches use null scope explicitly)

8. **rollout feature resolves consistently for same scope**
   - Create Organization, set TenantContext
   - First check: `$result = Feature::active('new-editor')`
   - Second check: `$result2 = Feature::active('new-editor')`
   - Assert `$result === $result2` (Pennant caches resolved value)

9. **Feature::for() allows checking against different organization**
   - Create two orgs
   - Set TenantContext to org1
   - Check `Feature::active('new-editor')` -- checks org1 (default scope)
   - Check `Feature::for($org2)->active('new-editor')` -- checks org2 (explicit scope)
   - Both should return booleans (may differ due to lottery)

10. **existing @canUseFeature system is unaffected**
    - Create User with plan that has limits
    - Verify `$user->canUseFeature('api_keys')` still works correctly
    - This confirms Pennant did not break the existing feature limit system

Use `RefreshDatabase` trait. Use existing factories: `User::factory()`, `Organization::factory()` (check if exists, otherwise create org manually), Plan factory, Subscription factory.

Check existing test file `tests/Feature/PlanFeatureLimitsTest.php` for factory usage patterns and test structure conventions.
  </action>

  <done>10 test cases covering scope resolution, all three flag types, scope independence, caching behavior, and backward compatibility with existing feature limit system.</done>
