  <name>Task 1: Install Pennant and configure tenant-scoped default resolution</name>
  <files>composer.json, config/pennant.php, app/Providers/AppServiceProvider.php</files>
  <action>
1. Install Pennant: `composer require laravel/pennant --no-interaction`
2. Publish Pennant config and migration: `php artisan vendor:publish --provider="Laravel\Pennant\PennantServiceProvider" --no-interaction`
3. Verify `config/pennant.php` uses `'database'` as default store (it should by default).
4. In `AppServiceProvider::boot()`, add Pennant default scope resolution BEFORE the existing event listeners:

```php
use Laravel\Pennant\Feature;

Feature::resolveScopeUsing(function ($driver) {
    $organizationId = app(\Wave\TenantContext::class)->get();
    if ($organizationId) {
        return \App\Models\Organization::find($organizationId);
    }
    return auth()->user();
});
```

This makes `Feature::active('flag')` check against the current organization when TenantContext has one, falling back to the authenticated user when there is no org context (personal billing context). Kill switches use `Feature::for(null)->active('flag')` explicitly.

5. Run `php artisan migrate` to create Pennant's `features` table.

Do NOT add `HasFeatures` trait to Organization or User models -- developers call `Feature::active()` directly, which is simpler and more explicit.
  </action>

  <action>
**FeatureFlagType enum** (`app/Enums/FeatureFlagType.php`):
- Cases: `PlanGated`, `Rollout`, `KillSwitch`
- String-backed: `'plan_gated'`, `'rollout'`, `'kill_switch'`
- Add `label(): string` method returning human-readable labels ("Plan-Gated", "Rollout", "Kill Switch")
- Add `color(): string` method returning Filament badge colors: PlanGated='info', Rollout='warning', KillSwitch='danger'

**feature_definitions migration** (use `php artisan make:migration create_feature_definitions_table --no-interaction`):
- `id` bigIncrements
- `name` string, unique -- matches the Pennant feature key (e.g., 'ai-reports')
- `type` string -- FeatureFlagType enum value
- `description` text, nullable -- human-readable description for admin context
- `is_active` boolean, default true -- global enable/disable (for kill switches, this IS the toggle; for others, Pennant manages per-scope state)
- `last_changed_by` foreignId nullable, constrained to users table, nullOnDelete
- `timestamps`

**FeatureDefinition model** (`app/Models/FeatureDefinition.php`):
- Use `php artisan make:model FeatureDefinition --no-interaction` then edit
- `$guarded = []`
- Casts: `type` => FeatureFlagType::class, `is_active` => 'boolean'
- Relationship: `changedBy()` belongsTo User (last_changed_by)
- No factory needed (seeder handles sample data)

**Example feature classes** (use `php artisan pennant:feature ClassName --no-interaction` for each):

1. `app/Features/AiReports.php` (Plan-Gated):
   - `#[Name('ai-reports')]` attribute (Laravel 12 uses the Name attribute, not $name property)
   - `resolve(mixed $scope): bool` -- If $scope is Organization, check `$scope->activeSubscription()?->plan?->features` array for 'ai-reports'. Return true if found, false otherwise. If $scope is not Organization, return false.
   - This demonstrates plan-gating: feature availability tied to subscription plan.

2. `app/Features/NewEditor.php` (Gradual Rollout):
   - `#[Name('new-editor')]` attribute
   - `resolve(mixed $scope): bool` -- Use `Lottery::odds(1, 10)` (10% rollout). Pennant caches the resolved value per scope in DB, so each org gets a consistent result after first check.
   - Import `Illuminate\Support\Lottery`.

3. `app/Features/MaintenanceMode.php` (Kill Switch):
   - `#[Name('maintenance-mode')]` attribute
   - `resolve(mixed $scope): bool` -- Return false (default off). Kill switches are toggled via `Feature::for(null)->activate('maintenance-mode')` in admin, checked via `Feature::for(null)->active('maintenance-mode')` in code. The resolve method only provides the initial default.

**FeatureDefinitionSeeder** (use `php artisan make:seeder FeatureDefinitionSeeder --no-interaction`):
- Insert 3 FeatureDefinition records matching the example feature classes:
  - name: 'ai-reports', type: PlanGated, description: 'AI-powered report generation. Available on Pro and Enterprise plans.'
  - name: 'new-editor', type: Rollout, description: 'New rich text editor. Rolling out to 10% of organizations.'
  - name: 'maintenance-mode', type: KillSwitch, description: 'Emergency kill switch for maintenance. Disables all non-essential features when activated.'
- Use `updateOrCreate` on `name` to be idempotent.

Run the migration and seeder: `php artisan migrate && php artisan db:seed --class=FeatureDefinitionSeeder --no-interaction`

Do NOT modify the Plan model's `features` JSON field -- plan-gated feature classes read from it as-is.
Do NOT modify `@canUseFeature` or HasPlanFeatures -- Pennant is additive, not a replacement.
